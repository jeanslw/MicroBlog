# 部署文档

涵盖 MicroBlog 从裸机三步快速启动到 Docker Compose 生产部署的全部内容。功能与项目总览见 [README](../README_ZH-CN.md)。

## 1. 快速部署

### 1.1 裸机快速启动（SQLite，3 步到位）

```bash
# 1. 安装依赖
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. 配置环境变量
export BLOG_SECRET_KEY="$(python -c 'import secrets;print(secrets.token_hex(32))')"
export BLOG_INIT_ADMIN_PWD='your-strong-password'

# 3. 启动（开发服务器）
python run.py
# 访问 http://127.0.0.1:5000，后台 http://127.0.0.1:5000/admin/login
```

> 生产环境请用 WSGI 服务器：Linux/WSL2 用 gunicorn，Windows 用 waitress，详见 [2.5 启动服务](#25-启动服务)。
> 未设置 `BLOG_INIT_ADMIN_PWD` 也能启动，首访 `/admin/login` 会自动跳转 `/admin/setup` 引导创建管理员。

### 1.2 Docker 一键启动（推荐生产）

只需复制配置示例、填写两个 MySQL 密码，其余保持默认即可：

```bash
# 1. 准备变量
cp .env.docker.example .env.docker
# 编辑 .env.docker，只需修改：MYSQL_ROOT_PASSWORD / MYSQL_PASSWORD
# （BLOG_SECRET_KEY、BLOG_INIT_ADMIN_PWD 均可留空：前者有测试默认值，后者走引导页）

# 2. 启动（web + db + nginx）
docker compose --env-file .env.docker --profile full up -d

# 3. 访问
# 首页：    http://localhost/
# 后台登录：http://localhost/admin/login （无管理员时自动跳转 /admin/setup 引导建号）
# 健康探针：http://localhost/healthz
```

> 只想最快体验、不装 MySQL：`docker compose up -d web`（SQLite，零配置、无需 .env.docker），访问 `http://127.0.0.1:5000`。

## 2. 详细部署

### 2.1 获取代码

```bash
git clone https://github.com/jeanslw/MicroBlog.git /opt/MicroBlog
cd /opt/MicroBlog
```

### 2.2 安装 Python 依赖

```bash
python3 -m venv .venv
source .venv/bin/activate   # Linux/Mac
# .venv\Scripts\activate    # Windows

pip install -r requirements.txt
```

### 2.3 配置（通过环境变量）

所有配置通过环境变量注入，**`config.py` 不必修改**。常见变量：

| 变量名 | 默认 | 说明 |
|--------|------|------|
| `BLOG_SECRET_KEY` | （随机生成） | Session/CSRF 密钥；**生产环境必须显式设置，否则拒绝启动** |
| `BLOG_ENV` | `development` | `production` 下默认启用 Secure Cookie（可用 `BLOG_COOKIE_SECURE` 覆盖） |
| `BLOG_DEBUG` | `False` | 调试模式（生产保持 False） |
| `BLOG_COOKIE_SECURE` | 开发 `false` / 生产 `true` | 会话 Cookie 是否仅 HTTPS 传输；**明文 HTTP 调试/内置 nginx 需设 `false`**，配置 HTTPS 后置回 `true` |
| `BLOG_CANONICAL_URL` | （无） | 站点固定外链域名（如 `https://blog.example.com`），用于重置密码邮件/RSS/sitemap，防 Host 头注入 |
| `BLOG_TRUSTED_HOSTS` | （无，不校验） | Host 白名单，逗号分隔；非白名单 Host 返回 400。生产建议设为真实域名 |
| `BLOG_PROXY_XFOR` / `BLOG_PROXY_XPROTO` / `BLOG_PROXY_XHOST` | `0` / `0` / `0` | 经一层反向代理时前两者设 `1`（取真实 IP/协议）；nginx 已转发 Host 头，`XHOST` 保持 `0` |
| `BLOG_DB_TYPE` | `sqlite` | `sqlite` 或 `mysql`；设为 `mysql` 但连接字段缺失时拒绝启动（不静默回退） |
| `BLOG_MYSQL_HOST` / `BLOG_MYSQL_USER` / `BLOG_MYSQL_PWD` / `BLOG_MYSQL_DB` | - | MySQL 连接信息 |
| `BLOG_SQLITE_PATH` | `data/blog.db` | SQLite 文件路径 |
| `BLOG_PAGE_SIZE` | `6` | 每页文章数 |
| `BLOG_STATIC_MAX_AGE` | `0` | 静态文件缓存秒数（compose 模板默认 43200） |
| `BLOG_INIT_ADMIN_USER` | `admin` | 首次启动自动创建的管理员账号 |
| `BLOG_INIT_ADMIN_PWD` | （无） | 自动创建管理员的密码，仅 admin 表为空时生效一次；**留空则不自动建号，首访 `/admin/setup` 按引导页创建** |

Linux 示例：

```bash
export BLOG_ENV=production
export BLOG_SECRET_KEY="$(python -c 'import secrets;print(secrets.token_hex(32))')"
export BLOG_DB_TYPE=sqlite
export BLOG_INIT_ADMIN_USER=admin
export BLOG_INIT_ADMIN_PWD='你的强密码'
```

Windows PowerShell 示例：

```powershell
$env:BLOG_ENV = "production"
$env:BLOG_SECRET_KEY = -join ((48..57)+(65..90)+(97..122) | Get-Random -Count 64 | % {[char]$_})
$env:BLOG_DB_TYPE = "sqlite"
$env:BLOG_INIT_ADMIN_PWD = "你的强密码"
```

#### 方式一：SQLite（推荐开发/测试）

无需额外配置，设置 `BLOG_DB_TYPE=sqlite` 即可，首次启动自动在 `data/` 目录建表；管理员可通过 `BLOG_INIT_ADMIN_PWD` 自动创建，或留空后首访 `/admin/setup` 引导创建（需确保 `data/` 目录可写）。

#### 方式二：MySQL（推荐生产环境）

1. 安装 MySQL 并创建数据库：

```sql
CREATE DATABASE flask_blog DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. 设置环境变量：

```bash
export BLOG_DB_TYPE=mysql
export BLOG_MYSQL_HOST=localhost
export BLOG_MYSQL_USER=root
export BLOG_MYSQL_PWD='你的MySQL密码'
export BLOG_MYSQL_DB=flask_blog
export BLOG_INIT_ADMIN_PWD='你的管理员密码'
```

3. 导入建表脚本（可选，应用启动时也会自动建表）：

```bash
mysql -u root -p flask_blog < MySQL/init.sql
```

### 2.4 手动建表 SQL（MySQL 用户参考）

直接使用 [`MySQL/init.sql`](../MySQL/init.sql)（已通过 STRICT_TRANS_TABLES 严格模式校验，含索引、字符集、字段长度适配）：

```bash
mysql -uroot -p < MySQL/init.sql
```

> ⚠️ **生产环境推荐启用 MySQL 严格模式**（默认已启用），避免数据被静默截断。

**关键字段长度说明**（已在 init.sql 中正确设置，手动建表时切勿缩小）：

| 字段 | 长度 | 原因 |
|------|------|------|
| `admin.password` | VARCHAR(255) | Werkzeug 3.x pbkdf2:sha256:600000 哈希约 102 字符 |
| `banner.img_path` | VARCHAR(500) | 上传路径含 UUID + secure_filename |
| `article.content` | MEDIUMTEXT | 文章正文，TEXT 仅 64KB，MEDIUMTEXT 16MB |
| `article.title` | VARCHAR(500) | 长标题兼容 |

### 2.5 启动服务

**开发/测试：**

```bash
python run.py
# 监听 http://127.0.0.1:5000
```

**生产部署：**

```bash
# 方案一：gunicorn（Linux / WSL2，Docker 镜像内置；多 worker 共享同一 BLOG_SECRET_KEY）
# 本机有 nginx 反代时绑回环地址；需直接对外提供访问才绑 0.0.0.0
gunicorn -w 4 -b 127.0.0.1:5000 --access-logfile - --error-logfile - "app:create_app()"
# 也可使用预构建的 WSGI 入口：gunicorn -w 4 -b 127.0.0.1:5000 wsgi:application

# 方案二：uWSGI（Linux）
uwsgi --ini uwsgi.ini

# 方案三：waitress（跨平台，Windows 生产/测试用；已包含在 requirements.txt）
waitress-serve --listen=127.0.0.1:5000 wsgi:application
```

> **经 nginx 等反向代理时**：设置 `BLOG_PROXY_XFOR=1`、`BLOG_PROXY_XPROTO=1`（`BLOG_PROXY_XHOST=0`），
> 并确保代理转发 `Host` 与 `X-Forwarded-*` 头（可直接复用 [nginx/nginx.conf](../nginx/nginx.conf)）。
> 明文 HTTP 调试还需 `BLOG_COOKIE_SECURE=false`，否则登录后会话不会回传。
> MySQL 模式下应用启动会自动等待数据库就绪（每 3 秒重试，最多 90 秒），无需额外 sleep 脚本。

### 2.6 Docker Compose 部署（推荐生产）

适合不希望手动配置 Python/MySQL/Nginx 的用户，一条命令拉起全套服务。

#### 2.6.1 服务器准备（首次部署必做）

```bash
# 安装 Docker + Compose 插件
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER   # 免 sudo，需重新登录生效
```

#### 2.6.2 准备变量文件

```bash
cp .env.docker.example .env.docker
vim .env.docker
```

`.env.docker` 变量分三类（**开箱只需填两个 MySQL 密码**）：

| 分类 | 变量 | 说明 |
|------|------|------|
| **必填** | `MYSQL_ROOT_PASSWORD` | MySQL root 密码，改强密码 |
| **必填** | `MYSQL_PASSWORD` | MySQL 业务账号 `blog` 的密码，改强密码（与应用连接自动保持一致） |
| 公网部署建议 | `BLOG_SECRET_KEY` | 留空使用内置测试默认密钥（公开、不安全）；上公网必须用 `python -c "import secrets;print(secrets.token_hex(32))"` 生成后填入 |
| 公网部署建议 | `BLOG_CANONICAL_URL` / `BLOG_TRUSTED_HOSTS` | 真实域名，防 Host 头注入 |
| 可选 | `BLOG_DB_TYPE` | 默认 `mysql`；改为 `sqlite` 后可不启用 db 服务 |
| 可选 | `BLOG_INIT_ADMIN_PWD` | 留空走 `/admin/setup` 引导页建号；填密码则首启自动创建（仅一次） |
| 可选 | `BLOG_COOKIE_SECURE` | 默认 `false`（内置 nginx 为明文 HTTP）；配置 HTTPS 后置 `true` |
| 可选 | `WEB_PORT` | web 直连端口宿主机映射，默认 `5000`，仅绑定 `127.0.0.1` |

> 模板内 `BLOG_PROXY_XFOR/XPROTO/XHOST` 已由 compose 设好正确默认值（1/1/0），无需修改。

#### 2.6.3 启动方式

**A. 完整模式（web + db + nginx，推荐生产）**

```bash
docker compose --env-file .env.docker --profile full up -d
```
- 访问：`http://localhost`（nginx 反代，80 端口）
- 直连 Flask（仅宿主机回环）：`http://127.0.0.1:5000`

**B. 仅 web + db（无 nginx，适合内部/调试/外接反代）**

```bash
docker compose --env-file .env.docker --profile mysql up -d
```
- 访问：`http://127.0.0.1:5000`（仅绑定宿主机回环地址；需对外请自行加反代或改 compose 端口映射）

**C. 仅 web（SQLite 单容器，最简，零配置）**

```bash
# 无需 .env.docker，也无需 --no-deps（db 依赖在未启用 profile 时自动忽略，需 Compose v2.20+）
docker compose up -d web
```
- 访问：`http://127.0.0.1:5000`，数据文件在宿主机 `./data/blog.db`
- 注：compose 会隐式读取项目根目录 `.env`，若其中含 `BLOG_DB_TYPE=mysql`，改用 `--env-file` 指定只含 `BLOG_DB_TYPE=sqlite` 的文件

#### 2.6.5 健康检查、启动顺序与目录权限

开箱编排内置以下保障，无需自行编写 wait 脚本：

| 机制 | 行为 |
|------|------|
| `/healthz` 探针 | web 容器健康检查访问 `GET /healthz`，应用执行 `SELECT 1`：成功返回 200，数据库异常返回 503；该路径豁免 Host 白名单 |
| db 健康检查 | MySQL 容器 `mysqladmin ping`，首启自动导入 [MySQL/init.sql](../MySQL/init.sql) |
| 启动顺序 | web `depends_on` db 健康通过（SQLite 模式该依赖自动忽略）；nginx `depends_on` web 健康通过后才接入流量 |
| 应用层等待 | web 启动时先等待 MySQL 可连接（每 3 秒探测、最多 90 秒），再建表/初始化，杜绝 MySQL 首启慢导致初始化被跳过 |
| 挂载目录权限 | 容器入口脚本 [docker-entrypoint.sh](../docker-entrypoint.sh) 自动修正 `./data`、`./static/banner`、`./static/uploads`、`./backups` 的属主后再降权运行（Linux 原生 Docker 下 bind mount 默认 root 属主的问题已自动处理） |

手动验证探针：

```bash
curl http://localhost/healthz        # 经 nginx，期望 {"status":"ok"}
curl http://127.0.0.1:5000/healthz   # 直连 web
```

#### 2.6.6 常用运维命令

```bash
# 查看日志
docker compose logs -f web
docker compose logs -f db

# 重启服务
docker compose restart web

# 停止并清理（保留卷）
docker compose down

# 停止并删除数据卷（慎用！清空数据库）
docker compose down -v

# 重新构建镜像（代码改动后）
docker compose build web
docker compose --env-file .env.docker --profile full up -d
```

#### 2.6.7 首次部署检查清单

| 检查项 | 命令 | 期望结果 |
|--------|------|----------|
| 容器状态 | `docker compose --env-file .env.docker --profile full ps` | 3 个 `Up`，web/db 显示 `(healthy)` |
| Web 日志 | `docker compose logs web \| tail -30` | 无 `ERROR`/`Traceback` |
| 健康探针 | `curl http://localhost/healthz` | `{"status":"ok"}` |
| 首页访问 | `curl -I http://localhost/` | `HTTP/1.1 200` |
| 后台页面 | `curl -I http://localhost/admin/login` | `HTTP/1.1 200`（无管理员时 302 跳 `/admin/setup` 也正常） |
| 管理员账号 | 浏览器首访 `/admin/setup` 建号后：`docker exec -i flask-blog-db mysql -uroot -p<密码> flask_blog -e "SELECT count(*) FROM admin"` | `count(*) >= 1`（未建号前为 0 是正常的） |
| 防火墙 | `sudo ufw status` | 仅放行 80/443；5000/3306 不对公网开放 |

#### 2.6.8 反代域名与 HTTPS

HTTPS 配置已在 [nginx/nginx.conf](../nginx/nginx.conf) 与 docker-compose.yml 中**完整写好并注释**，按以下步骤取消注释即可，无需手写配置：

1. 将证书放入宿主机 `./nginx/certs/`：`fullchain.pem`（含完整链）与 `privkey.pem`（私钥）；该目录已在 `.gitignore` 中，不会误提交
2. 编辑 `docker-compose.yml` 的 nginx 服务，取消 `#- "443:443"` 与 `#- ./nginx/certs:/etc/nginx/certs:ro` 两行注释
3. 编辑 `nginx/nginx.conf`：取消文件末尾整个 443 server 块的注释，将其中 `server_name` 改为真实域名；再取消 80 server 中 `#return 301 https://$host$request_uri;` 的注释（HTTP 自动跳转 HTTPS）
4. 在 `.env.docker` 中设置 `BLOG_COOKIE_SECURE=true`（`BLOG_PROXY_XPROTO=1` compose 已默认开启，应用可正确识别 HTTPS 协议）
5. 重建：`docker compose --env-file .env.docker --profile full up -d`，用 `docker exec flask-blog-nginx nginx -t` 验证配置

> 443 块内含 TLS 1.2/1.3、现代加密套件与会话缓存。安全响应头（CSP/X-Frame-Options/nosniff/Referrer-Policy/HSTS）、静态资源缓存与上传资源防盗链均由应用层统一下发（`app/__init__.py`），nginx 仅做纯转发，勿在 nginx 重复 `add_header`（多份 CSP 浏览器取交集执行）。
> 使用 Let's Encrypt HTTP-01 验证申请/续期证书时，需临时注释 80 端口的 301 跳转（或改用 DNS-01）。

生产环境**仅开放 80/443**，不要把 5000（Flask）和 3306（MySQL）暴露到公网（当前 compose 已将 5000 绑定到回环地址、3306 默认不映射）。
