# 管理员手册

面向**自部署 MicroBlog 的站长/管理员**：后台入口、各功能页怎么用、日常运维（备份/恢复/数据库迁移）、账号安全与排障。

- 首次部署、环境变量、HTTPS、Docker 见[部署文档](部署文档.md)；
- 报错排查见[常见问题](常见问题.md)；
- 代码结构与模块划分见[项目架构](项目架构.md)。

> 本手册描述的是**后台界面**操作。所有写操作都经表单校验并带 CSRF 令牌，界面文案可通过 `BLOG_LOCALE`/页面右上角切换中英。

## 2. 登录与账号

### 2.1 首次安装：创建管理员

数据库 `admin` 表为空时，`/admin/login`、`/admin/panel` 等页面会**自动重定向**到 `/admin/setup` 首次安装引导：

- 填写账号、邮箱（选填，用于找回密码，可稍后在后台补）、密码（6–128 位）、确认密码；
- 提交即创建管理员并写入数据库，随后跳转登录。

不想用页面引导时，可用命令行/环境变量创建：

```bash
# 方式一：启动时自动创建（仅当 admin 表为空）
# app.env: BLOG_INIT_ADMIN_USER=admin（默认）、BLOG_INIT_ADMIN_PWD=你的强密码

# 方式二：交互式命令（幂等：账号已存在则跳过）
flask create-admin
```

> 初始化完成后建议**删除 `BLOG_INIT_ADMIN_PWD`**，避免它长期留在配置文件里。

### 2.2 登录与退出

- 登录：`/admin/login`。登录成功后会跳回 `?next=` 指定的**站内相对路径**（如从维护页跳来时会回到迁移页）；`next` 只接受站内路径，防止开放重定向。
- 会话：登录后使用永久会话，默认有效期 **24 小时**（`BLOG_SESSION_LIFETIME`，单位秒）；生产环境 Cookie 带 `Secure`（`BLOG_COOKIE_SECURE=true`）、`HttpOnly`、`SameSite=Lax`。
- 退出：后台菜单「退出登录」（POST + CSRF），退出会清空整个会话。

### 2.3 登录失败锁定（防暴力破解）

- 计数维度：**同一 IP + 同一账号**；连续失败 **5 次**后锁定 **5 分钟**，锁定期内登录返回 `429` 并提示剩余秒数。
- 计数持久化在 `login_attempt` 表（跨 worker 共享，重启不丢），**登录成功后自动清零**。
- 在哪看：后台「账户安全 → 账户邮件设置」页底部「登录失败记录」，列出最近 10 条（IP / 失败次数 / 最近失败时间 / 状态：已锁定 or 正常）。
- 被自己锁住的等 5 分钟即可；也可在数据库里清空对应行（`DELETE FROM login_attempt`）。

### 2.4 忘记密码（邮箱找回）

1. `/admin/forgot` 填**账号 + 绑定邮箱**（两者都必须与后台记录一致）；
2. 系统发一封含一次性令牌的邮件，链接地址为 `/admin/reset/<token>`；
3. 令牌 **30 分钟**内有效（`BLOG_RESET_TOKEN_MAX_AGE`），且**改密后立即失效**（令牌载荷绑定当前密码哈希，天然单次有效）。

安全设计（与后台行为一致，便于排查）：

- 无论账号是否存在、邮件是否发送成功，页面都返回同一句提示 —— 防止账号枚举；
- 找回接口按 IP 限流：**5 分钟 5 次**；
- 邮件依赖 SMTP：没配 SMTP 时收不到邮件，请用 §8.2 的命令行方式重置密码。

### 2.5 修改密码

后台「账户安全 →修改密码」，需要输入原密码；新密码 6–128 位。修改成功后**强制退出登录**（其他设备上的会话同时失效），需用新密码重新登录。

## 3. 后台菜单总览

侧边菜单（窄屏为抽屉）分四组：

| 分组 | 菜单项 | 地址 | 说明 |
|------|--------|------|------|
| （顶部） | 站点设置 | `/admin/site_setting` | 站点名、Logo、背景、栏目样式、评论开关；`/admin/panel` 为同一表单 |
| （顶部） | 关于我 | `/admin/about_setting` | 前台「关于我」页内容 |
| 文章管理 | 草稿箱 | `/drafts` | 未发布文章 |
| 文章管理 | 新建文章 | `/article/new` | Markdown 编辑器 |
| 文章管理 | 文章列表 | `/article/manage` | 已发布文章的置顶/编辑/撤回/删除 + 评论管理入口 |
| 轮播图管理 | 轮播图列表 | `/banner/` | 新增、编辑、撤回/启用、删除 |
| 轮播图管理 | 新建轮播图 | `/banner/`（页内新增） | 上传图片 + 标题/链接/描述/排序 |
| 账户安全 | 修改密码 | `/admin/change_pwd` | 改登录密码 |
| 账户安全 | 账户邮件设置 | `/admin/account` | 账户邮箱、SMTP、发测试邮件、登录失败记录 |
| 账户安全 | 退出登录 | `/admin/logout` | POST 退出 |
| 运维安全 | 数据库备份 | `/admin/backup` | 立即备份 / 下载 / 恢复 / 删除 |
| 运维安全 | 迁移数据库 | `/admin/migrate` | 版本状态、执行迁移、迁移履历 |

> 栏目（分类）管理不在后台菜单里，而在**前台侧栏**（见 [§6.5](#65-栏目分类管理)）——因为它是博客内容结构的一部分，管理员登录后前台页面会多出编辑按钮。

## 4. 站点设置

后台「站点设置」（或后台首页）一张表单，保存后立即生效：

| 项 | 说明 |
|----|------|
| 网站名称 | 最长 100 字符；显示在导航栏、标题、页脚 |
| 网站 Logo | jpg/jpeg/png/webp，≤2MB；上传后自动缩放，最长边不超过 400px；留空则用默认图标 |
| 背景风格 | 内置图库（背景 1–10、`vdysjx`、`bg13`）+「自定义图片」+「经典」 |
| 自定义背景图片 | 可填图片 URL（`/uploads/image/backgrounds/xxx.jpg` 或 `http(s)://...`），也可直接上传本地图片（自动缩放到 1920 宽） |
| 栏目分类样式 | **书本树形**（书本图标可展开，阅读页深浅色自适应）或**经典简洁**（传统折叠箭头） |
| 评论设置 | 「开启评论」关闭后**全站禁止新评论与回复**（已有评论照常展示） |

关于背景风格的两层关系：

- 后台设置是**默认值**，输出到 `<body data-bg="…">`；
- 前台访客可用页面上的风格切换器**临时切换**，选择记录在浏览器 `localStorage`（key `blog-bg-style`），**优先于**后台默认值（只影响该访客自己的浏览器）；
- 访客想回到后台默认值，清除浏览器本地存储即可。

数据存放在 `site_setting` 单行表（v1.3.6 起由旧的 `site_config` 单表拆分而来，见 [§9](#9-升级与数据库结构迁移)）。

## 5. 关于我

后台「关于我」用于维护前台「关于我」页面（`/about`）：

| 字段 | 限制 |
|------|------|
| 头像 | 上传 jpg/jpeg/png/webp（≤2MB，长边自动缩到 512px）、填外链 URL、或勾选「清除当前头像」 |
| 昵称 | ≤100 字符；显示在文章详情页与「关于我」页 |
| 邮箱 | ≤200 字符，需为合法邮箱 |
| GitHub 链接 / 个人主页 | 各 ≤200 字符 |
| 个人简介 | ≤2000 字符，支持多行（换行会保留） |

> 头像的优先级：**上传文件 > 外链 URL > 清除 > 保持不变**；外链地址会回填到输入框，本地上传产生的内部路径不回填（避免误改成失效路径）。
> 页面右上角有「查看前台效果」直达 `/about`。

数据存放在 `about_profile` 单行表。

## 6. 内容管理

### 6.1 新建 / 编辑文章

后台「文章管理 →新建文章」（`/article/new`），编辑已有文章从「文章列表」或草稿箱进入：

| 项 | 说明 |
|----|------|
| 文章标题 | 必填，≤500 字符 |
| 所属栏目 | 可选「无分类」；栏目在[前台侧栏](#65-栏目分类管理)维护 |
| 正文 | Markdown 编辑器（支持工具栏插入代码块、加粗/斜体/链接/图片）；必填 |
| 上传 Markdown | 选择 `.md`/`.markdown` 文件（≤2MB）导入正文，导入会**覆盖**当前正文 |
| 上传图片 | jpg/jpeg/png/gif，≤10MB；上传后插入到光标处（本地存储，不走 CDN） |
| 插入媒体 | 图片 / 音频等媒体类型 |
| SEO 描述 | ≤300 字符，留空则自动从正文生成 |
| SEO 关键词 | ≤300 字符，逗号分隔；留空则从栏目/标题自动生成 |
| 保存方式 | 「存入草稿（仅后台可见）」或「公开发布（所有人可见）」 |

- 编辑页会**自动保存草稿**，防止误关页面丢内容；
- 编辑器支持实时预览（右边栏「实时预览」）。

### 6.2 文章列表

后台「文章管理 →文章列表」（`/article/manage`）：

- 列表列：标题、栏目、更新时间、评论数、操作；
- 操作：
  - **置顶 / 取消置顶**（首页与列表页排序靠前）；
  - **编辑**（打开编辑页）；
  - **撤回**（把已发布文章退回草稿箱，前台不再可见）；
  - **删除**（不可恢复）；
  - **评论管理**（进入该文章的评论/回复管理页）。

### 6.3 草稿箱

后台「文章管理 →草稿箱」（`/drafts`）列出所有未发布文章，可编辑修改或删除（删除会二次确认）。前台与搜索引擎都看不到草稿。

### 6.4 评论与回复管理

从文章列表点「评论管理」进入（`/comment/manage/<文章 id>`）：

- 展示该文章的全部评论与回复（含数量统计），可跳转查看前台文章或返回列表；
- **删除评论会连带删除其下的全部回复**（有明确提示）；
- 回复可单独删除。

前台访客侧还有两道防刷限制（按 IP，数据库 `rate_limit` 表）：**评论/回复 5 分钟 10 次**、**点赞 5 分钟 20 次**。

### 6.5 栏目（分类）管理

栏目管理入口在**前台页面右侧栏**（首页、文章列表、详情页等共用同一侧栏）：

- 登录管理员后，「栏目分类」树中每个栏目右侧会出现重命名/删除按钮：
  - **重命名**：弹出输入框改名（≤60 字符）；
  - **删除**：二次确认，**该栏目下的文章会变为「未分类」**（文章不会删除）；
- 侧栏底部「新建栏目」表单：填栏目名称（必填，≤60）与标签（选填，≤60）后「添加分类」；
- 栏目树显示每个栏目下的文章标题（可折叠展开）与文章计数，栏目删除/改名即时生效。

> 栏目数据存 `category` 表；标签用于前台栏目页的展示标记。

## 7. 轮播图管理

后台「轮播图管理 →轮播图列表」（`/banner/`），也可从首页轮播区进入：

| 字段 | 说明 |
|------|------|
| 轮播图片 | jpg/jpeg/png/gif，≤10MB；上传后自动缩放到 1920 宽（编辑时可选新图，「不换留空」） |
| 标题 | ≤100 字符 |
| 跳转链接 | ≤500 字符；留空表示点击不跳转 |
| 描述文字 | ≤200 字符 |
| 排序权重 | 整数，**数值越大越靠前** |

列表列与操作：

- 列：预览、标题、跳转链接、排序权重、状态、**最近变更**、操作；
- **状态**：`展示中` / `已撤回`；
- 操作：
  - **编辑**（可换图/改文字/改排序）；
  - **撤回**：首页不再展示，可随时重新**启用**（撤回时间会记入「最近变更」列）；
  - **删除**（二次确认，不可恢复）；
- 只有「展示中」的轮播图会出现在首页；「最近变更」列显示该轮播图最后一次变动的时间（v1.3.6 起新增 `banner.update_time`）。

## 8. 账户与运维安全

### 8.1 账户邮件设置（`/admin/account`）

一块表单管三件事：

1. **账户邮箱**：用于忘记密码找回，请确保能正常收信（≤200 字符，需合法邮箱）；
2. **SMTP 邮件设置**（用于发送找回密码等邮件）：
   - SMTP 服务器、端口（1–65535，默认 587）、用户名、密码/授权码、发件人邮箱；
   - **密码留空则保持原密码不变**（避免每次保存都要重填）；
   - 「使用 STARTTLS（587 端口）」/「使用 SSL（465 端口）」二选一（按你的邮箱服务商要求）；
   - 「发送测试邮件」：测试邮件发送到**上方账户邮箱**，用于验证配置；
   - **优先级**：后台保存的 SMTP 配置 **优先于** `app.env` 里的 `BLOG_MAIL_*`（`mail_setting.mail_host` 非空即视为已配置）；
3. **登录失败记录**：最近 10 条（见 [§2.3](#23-登录失败锁定防暴力破解)）。

### 8.2 数据库备份与恢复（`/admin/backup`）

- **立即备份**：生成一份当前数据库备份，显示在下方列表中（文件名 / 大小 / 时间）；
- 每行操作：**下载**、**恢复**、**删除**；
- 备份文件保存在项目根目录 `backups/` 下；
- 当前数据库类型会显示在页面上（Docker 镜像已内置 `mysqldump`/`mysql`，备份与恢复开箱即用）。

> **恢复是高危操作**：会用备份文件**覆盖当前全部数据**且不可撤销。界面会提示，并要求先「立即备份」当前数据；系统在执行恢复前也会**自动备份当前数据**。恢复期间请不要访问后台或写入数据（有进程内 + 跨进程文件锁保护并发）。
>
> **SQLite 特别注意**：恢复完成后必须**手动重启服务**（gunicorn/uwsgi），否则其他 worker 可能仍持有旧数据。

### 8.3 命令行兜底

命令行在项目根目录执行（需先激活虚拟环境并设置好 `app.env`）：

| 命令 | 作用 |
|------|------|
| `flask init-db` | 建表 + 执行待应用的 schema 迁移 + 补默认设置/管理员（**幂等**，可反复执行） |
| `flask create-admin` | 交互式创建管理员（账号已存在则跳过） |

忘记密码且邮箱/SMTP 不可用时，最省事的办法是：

```bash
# 1) 用 init-db 确保表结构就绪（幂等）
flask init-db
# 2) 交互式创建/确认管理员账号（若忘记的账号已存在，可改用数据库改密码或新建另一个账号）
flask create-admin
```

### 8.4 日志与健康检查

- 应用日志落盘在 `logs/app.log`（默认 10MB × 5 份轮转，可用 `BLOG_LOG_*` 调整）；控制台同步输出；
- 生产环境输出 **JSON 结构化日志**（ELK/Loki 可直接解析），每个请求带 `X-Request-ID` 串联链路；
- 慢请求（`BLOG_SLOW_REQUEST_MS`，默认 500ms）与慢 SQL（`BLOG_SLOW_QUERY_MS`，默认 200ms）会打告警日志；
- 健康检查 `GET /healthz`：**维护模式下也可访问**，适合给负载均衡/探针使用。

## 9. 升级与数据库结构迁移

v1.3.6 起，程序把数据库结构（schema）版本**记录在库里**（`schema_version` 履历表），升级程序后由「迁移数据库」页或启动流程自动对齐。

### 9.1 版本比较与触发规则

| 程序版本 vs 数据库版本 | 行为 |
|------------------------|------|
| 程序 **>** 数据库 | 存在待迁移项 → 自动模式立即迁移；手动模式进入维护状态，等管理员执行 |
| 相等 | 无需迁移 |
| 程序 **<** 数据库（代码被降级） | **告警并跳过**，绝不用旧代码去碰比它新的库 |

### 9.2 两种模式（`BLOG_AUTO_MIGRATE`）

| 模式 | 配置 | 升级后的表现 |
|------|------|--------------|
| 自动（默认） | 不写该变量，或 `BLOG_AUTO_MIGRATE=true` | 启动时自动执行迁移，站点正常对外服务 |
| 手动 | `BLOG_AUTO_MIGRATE=false` | 启动**不动数据库**；检测到待迁移时全站返回 **HTTP 503** 维护页（`/admin/upgrade_required`），只有静态资源、`/healthz`、上传文件、后台登录/退出、迁移页可访问 |

### 9.3 手动模式下的恢复步骤

1. **先备份**：维护模式下后台「数据库备份」页**不在白名单**（访问会返回 503），所以请在**升级前**就备份好数据库；若已经进入维护模式，可在服务器上手工备份（SQLite 直接复制 `data/blog.db`，MySQL 用 `mysqldump`）。
2. 访问 `/admin/login?next=/admin/migrate` 登录后台（登录入口在维护模式下**始终可用**）；
3. 打开「运维安全 → 迁移数据库」，页面显示当前数据库版本、程序目标版本、待应用的迁移列表；
4. 点「执行迁移」（会二次确认）；
5. 完成后维护页自动消失 —— 闸门**每个请求自检**：只要数据库版本追上程序版本，无论迁移是本进程、其他 worker 还是 CLI 完成的，都会自动放行，**无需重启**。

### 9.4 「迁移数据库」页的四种状态

| 提示 | 含义 | 怎么办 |
|------|------|--------|
| 绿色「已是最新 schema 版本」 | 数据库版本 == 程序版本 | 无需操作 |
| 黄色「检测到待应用的数据库迁移」 | 有迁移待执行，列出目标版本与说明 | 建议先备份 →「执行迁移」 |
| 黄色「数据库版本落后，但程序中没有登记可用的迁移」 | 程序包不完整/发布遗漏 | **确认是否完整部署了新版本程序**（不要手工改库） |
| 红色「数据库版本高于程序版本」 | 数据库比程序新：你在用旧代码运行新库 | 先升级程序（迁移已被跳过） |
| 红色「无法读取数据库版本」 | 数据库连接/权限异常 | 检查数据库连接与账号权限后重试 |

页面下方「迁移履历」列出每次迁移的版本、应用时间与说明（来自 `schema_version` 表）。

### 9.5 关键保障（为什么会这样设计）

- **失败不戳记**：某个迁移执行抛异常时，框架**不会**把该版本标记为已应用 —— 下次启动/手动触发会**自动重试**，不会出现"版本已更新但数据没迁"的静默失败；
- **并发安全**：MySQL 下用命名锁（`GET_LOCK`）串行化迁移，多 worker 同时启动只有一个真正执行，其余超时后记 warning 跳过；SQLite 为单进程场景，无需该锁；
- **迁移即幂等**：每个迁移函数都能重复执行（例如 `site_config` 拆分完成后旧表被删除，重跑直接跳过）；
- **同一入口**：启动自动迁移、后台手动迁移、`flask init-db` 都调用同一个 `run_schema_migrations`，行为一致；
- **不做自动降级**：框架只把**旧库**往新版本带。想回退版本，请用升级前的备份恢复数据库（见 [§8.2](#82-数据库备份与恢复adminbackup)）。

### 9.6 维护模式下为什么还能登录

维护模式下数据库可能缺少新版本才有的列/表，因此**只有三张表跨版本不变**（`admin`、`login_attempt`、`rate_limit`），登录是迁移的唯一入口 —— 这点在排查「维护页按钮点不动」时很有用：确认用的是 `/admin/login`，而不是前台的任意页面。

更完整的部署侧说明（含 MySQL/SQLite 差异、回滚注意、备份建议）见[部署文档 §2.8 升级与数据库结构迁移](部署文档.md#28-升级与数据库结构迁移)。

## 10. 与后台行为相关的环境变量

以下变量影响后台/管理员体验（完整清单与默认值见[部署文档](部署文档.md)变量表）：

| 变量 | 默认 | 影响 |
|------|------|------|
| `BLOG_AUTO_MIGRATE` | `true` | 自动/手动迁移模式（见 [§9.2](#92-两种模式blog_auto_migrate)） |
| `BLOG_INIT_ADMIN_USER` / `BLOG_INIT_ADMIN_PWD` | `admin` / 空 | 库为空时自动创建管理员（建议首次初始化后删除密码项） |
| `BLOG_MAIL_*`（HOST/PORT/USER/PASSWORD/FROM/USE_SSL/USE_TLS） | 空 / 587 / … | SMTP 兜底配置；**后台保存的配置优先** |
| `BLOG_RESET_TOKEN_MAX_AGE` | `1800` | 找回密码令牌有效期（秒） |
| `BLOG_SECRET_KEY` / `BLOG_SECRET_KEY_FILE` | 开发随机 | 会话与令牌签名密钥；生产必须显式设置（公开默认值会拒绝启动） |
| `BLOG_SESSION_LIFETIME` | `86400` | 登录会话有效期（秒） |
| `BLOG_COOKIE_SECURE` | 生产 `true` | Cookie 是否带 `Secure`（纯 HTTP 环境需设 `false`） |
| `BLOG_PAGE_SIZE` | `6` | 前台列表每页条数 |
| `BLOG_STATIC_MAX_AGE` | `0`（开发） | 静态资源缓存秒数（生产建议 30 天） |
| `BLOG_LOG_*` / `BLOG_SLOW_REQUEST_MS` / `BLOG_SLOW_QUERY_MS` | 见部署文档 | 日志轮转、慢请求/慢 SQL 告警阈值 |
| `BLOG_TRUSTED_HOSTS` | 空 | Host 白名单；填错会导致 400（含后台页面） |

> 存放位置：裸机为本项目根目录的 `app.env`（模板 `app.env.example`）；Docker 为 `.env.docker`（模板 `.env.docker.example`）。改完需**重启服务**生效。

## 11. 安全建议

- **只保留一个管理员账号**：系统设计为单管理员站点，没有角色/多用户概念；`flask create-admin` 只在需要时新建。
- **生产必开 HTTPS**，并保持 `BLOG_COOKIE_SECURE=true`；`BLOG_SECRET_KEY` 用随机长串并保密（用 `BLOG_SECRET_KEY_FILE` 可避免密钥出现在环境变量快照里）。
- **定期备份并下载到站外**：后台「数据库备份」的备份文件默认留在服务器 `backups/`，服务器故障会一起丢；建议下载留存。
- **升级前先备份**（尤其是手动模式下），迁移完成后再恢复对外服务。
- **关闭 `BLOG_DEBUG`**：生产环境隐藏异常堆栈，只返回通用错误页。
- 上传仅允许图片类型、有大小与像素上限；`/uploads/banner/`、`/uploads/image/` 有应用层 Referer 防盗链。
- 后台地址固定在 `/admin`。若希望降低被扫描概率，可在 Nginx 层对 `/admin` 做 IP 白名单或额外 Basic Auth。
- 安全响应头（CSP 等）由应用统一下发；**不要在 Nginx 重复下发 CSP**（多份 CSP 会被浏览器取交集，容易莫名拦截资源）。

## 12. 常见管理员任务速查

| 任务 | 操作 |
|------|------|
| 改站点名 / Logo / 背景 / 关评论 | 后台「站点设置」→ 保存 |
| 忘记密码但能收邮件 | `/admin/forgot` 邮箱找回 |
| 忘记密码且收不到邮件 | `flask create-admin` 新建账号，或用数据库客户端改 `admin` 表（密码需 Werkzeug 哈希） |
| 被登录锁定 | 等 5 分钟；或清空 `login_attempt` 表对应行 |
| 站点全是 503「站点维护中」 | 登录 `/admin/login?next=/admin/migrate` → 执行迁移（见 [§9.3](#93-手动模式下的恢复步骤)） |
| 升级程序 | 备份 → 替换代码/镜像 →（手动模式）执行迁移 → 观察 `/healthz` |
| 换域名 | 更新 `BLOG_TRUSTED_HOSTS` / `BLOG_CANONICAL_URL` / `BLOG_SECRET_KEY` 不变 → 重启 |
| 网站被灌水评论 | 关闭评论（站点设置）→ 在评论管理中清理 → 必要时在 Nginx 限流 |
| 想让文章先隐藏 | 文章列表「撤回」到草稿箱，或编辑时存为草稿 |
| 迁移数据库页红字「数据库版本高于程序」 | 你部署了旧代码：先升级程序，不要动数据库 |
