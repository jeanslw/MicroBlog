# MicroBlog 更新日志

## [v1.3.4] - 2026-09-12

安全防护职责迁移：响应头/缓存/防盗链由 nginx 配置层移入应用层，nginx 退化为纯转发。

### 变更与修复

- 安全响应头统一下发至应用层（`app/__init__.py` `after_request`）：CSP（含外链音视频所需的 `media-src 'self' https:`）、`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy`、HTTPS 下的 HSTS；CSP 策略收敛为配置项 `CSP_POLICY`。防护随代码进版本库、有测试覆盖，与部署方式（nginx/直连/Docker）无关。
- 上传资源防盗链迁至应用层（`before_request`）：`/static/banner/`、`/static/uploads/` 对空 Referer、同源与 Host 白名单站点放行，其余 403，对齐原 nginx `valid_referers` 行为；白名单未配置时仅同源放行。
- 静态资源缓存策略迁至应用层：`BLOG_STATIC_MAX_AGE > 0` 时静态响应携带 `Cache-Control: public, max-age=N, immutable`（Docker 模板默认 43200），开发默认 0 不缓存。
- nginx 配置简化为纯转发：移除 `add_header` 安全头、静态文件 location 与 `client_max_body_size`（请求体上限由应用 `MAX_CONTENT_LENGTH`=16MB 强制）；⚠️ 切勿在 nginx 重复下发 CSP——浏览器对多份 CSP 取交集执行。
- 澄清首次安装提示：未设置 `BLOG_INIT_ADMIN_PWD` 时启动日志由误导性的 warning（"请设置后重启"）改为说明性 info——留空是正常路径，首访后台会自动跳转 `/admin/setup` 引导页建号；引导页提交补齐多 worker 并发建号的 IntegrityError 竞争防护（他人抢先建号时优雅跳转登录页而非 500）。

### 测试与文档

- 新增 `tests/test_security_headers.py` 13 项测试：安全头全量断言（含 `media-src` 回归防护）、错误响应携带安全头、HTTP 无/HTTPS 有 HSTS、静态缓存开关、防盗链五类场景；新增 `tests/test_setup.py` 8 项测试：无管理员时后台路由跳转引导页、建号自动登录、密码校验、已有管理员时引导页失效、并发建号竞争；全量 **240 项**测试通过。
- 中英文部署文档同步说明安全头/防盗链的职责归属。

## [v1.3.3] - 2026-09-12

Docker Compose 开箱即用改造、容器健康探针与数据库就绪等待，并修复 nginx 反向代理下的登录问题。

### 新增

- 健康探针 `GET /healthz`：应用执行 `SELECT 1` 检测数据库连通性，成功返回 `{"status":"ok"}`（200），异常回滚并返回 503；该路径豁免 Host 白名单，供容器健康检查与负载均衡探测。
- 应用启动 MySQL 就绪等待（`wait_for_database`）：仅 MySQL 模式生效，每 3 秒探测一次、最多等待 90 秒，SQLite 立即通过；gunicorn / waitress 直连部署同样受益，杜绝 MySQL 首启初始化慢导致建表与初始数据被跳过。
- Docker 镜像新增入口脚本 `docker-entrypoint.sh`：以 root 启动后自动修正 bind mount 目录（`data`、`static/banner`、`static/uploads`、`backups`）属主，再通过 gosu 降权为 appuser 运行，解决原生 Linux Docker 挂载目录 Permission denied。
- 依赖新增 waitress 3.0.2：Windows 本地使用 `waitress-serve --listen=127.0.0.1:5000 wsgi:application` 启动（gunicorn 依赖 fork 不支持 Windows）。

### 变更与修复

- docker-compose 开箱即用：`BLOG_SECRET_KEY`、数据库密码等提供仅用于测试的内置默认值，复制 `.env.docker.example` 后**只需填写 `MYSQL_ROOT_PASSWORD` 与 `MYSQL_PASSWORD`** 即可启动；SQLite 模式 `docker compose up -d web` 零配置、无需 env 文件。
- 编排就绪顺序：web `depends_on` db 健康检查（`required: false`，SQLite 模式自动忽略，需 Docker Compose v2.20+），nginx 等 web 健康后才接入流量；db 与镜像 HEALTHCHECK 均基于 `mysqladmin ping` / `/healthz`。
- 修复经 nginx 反代后登录失败、登录后反复跳回登录页：内置 nginx 仅提供明文 HTTP(80)，compose 默认 `BLOG_COOKIE_SECURE=false`，配置 HTTPS 后置 `true`；compose 内置反代头参数 `BLOG_PROXY_XFOR=1`、`BLOG_PROXY_XPROTO=1`、`BLOG_PROXY_XHOST=0`。
- 修复 nginx `/healthz` 代理 `proxy_pass` 尾斜杠把路径重写为首页的问题，并补齐 `Host` 转发头。
- Host 白名单配置键由 `TRUSTED_HOSTS` 更名为 `HOST_WHITELIST`：Flask 3.1 会原生消费 `TRUSTED_HOSTS` 并在请求上下文阶段（早于 `before_request`）直接返回 400，无法按路径豁免探针；环境变量名 `BLOG_TRUSTED_HOSTS` 保持不变。
- web 容器端口仅映射到宿主机回环 `127.0.0.1:5000`（可用 `WEB_PORT` 改端口），MySQL 3306 默认不对外暴露。
- nginx 预置完整 HTTPS(443) 配置模板（默认整段注释）：TLS 1.2/1.3、现代加密套件、会话缓存、HSTS、与 80 一致的安全头/防盗链 location，以及 80→443 的 301 跳转开关；docker-compose 同步预置注释态的 443 端口与 `./nginx/certs` 证书目录只读挂载，`.gitignore` 忽略证书目录。启用 HTTPS 只需放证书、取消注释、设置 `BLOG_COOKIE_SECURE=true`，无需手写配置。
- Font Awesome 4.7.0 本地化：EasyMDE 编辑器运行时会动态注入 `maxcdn.bootstrapcdn.com` CDN 的 Font Awesome 样式表，经 nginx 时被站点 CSP（`style-src 'self'`）拦截，导致编辑器工具栏图标显示为空白方框；现将 CSS 与 5 个 webfont 字体文件内置于 `static/lib/`（字体 `url()` 路径改写为 `./fonts/`），编辑页引入本地样式表并加 `?v=4.7.0` 缓存击穿，EasyMDE 初始化设置 `autoDownloadFontAwesome: false`——全站零第三方 CDN 请求，可完全离线运行。

### 测试与文档

- 新增 `tests/test_health.py` 5 项测试：探针 200/503、探针豁免 Host 白名单、MySQL 重试至就绪、SQLite 跳过等待；全量 **219 项**测试通过。
- 中英文 README 新增「快速开始」章节（Docker Compose 三种 profile + 本机 gunicorn/waitress）；部署文档新增健康检查/启动顺序/目录权限说明，FAQ 新增反代登录失败、Host 白名单 400、探针 503、挂载权限、Windows waitress 等条目。

## [v1.3.2] - 2026-09-11

首次安装引导、邮件找回密码、数据库备份恢复、文章 SEO 与 sitemap，以及安全加固与后台界面统一改版。

### 新增

- 首次安装引导（`/admin/setup`）：无管理员时所有后台路由跳转至此，创建初始账号（账号/邮箱/密码）后自动登录。
- 邮件找回密码：`Admin` 新增 `email` 字段（幂等迁移）与账户邮箱管理页；`/admin/forgot` + `/admin/reset` 使用签名令牌（单次有效、30 分钟过期、绑定当前密码哈希）。
- 数据库备份与恢复：SQLite 文件复制 + MySQL `mysqldump`/`mysql`，支持列表/下载/删除/恢复；恢复前自动生成回滚快照（统一命名 `*_snapshot.zip`）。
- 文章 SEO 元数据：可选的描述/关键词（留空从正文与栏目自动生成），渲染为 `<meta>` 与 Open Graph 标签。
- `sitemap.xml`（并在 `robots.txt` 声明 `Sitemap:`）。
- 文章目录（TOC，h1–h3）：锚点跳转 + 滚动高亮。
- 置顶文章标题前显示「[置顶]」标识。
- 邮件设置页新增「发送测试邮件」按钮：一键验证 SMTP 配置，测试邮件发送到管理员邮箱。
- 站点设置新增「栏目分类样式」：书本树形（书本图标替代「>」箭头、可展开、深浅色自适应）与经典简洁两种，卡片式单选切换。

### 安全

- `site_config.mail_password` 使用 Fernet 加密存储（密钥由 `SECRET_KEY` 派生），后台表单不回显。
- 备份/恢复文件名经 `werkzeug.safe_join` 校验，防路径穿越（CodeQL path-injection）。
- 找回密码无论是否命中均返回同一提示，防账号枚举。
- 修复登录路由缩进缺陷：密码错误时不再可能错误建立登录态；失败锁定提示剩余尝试次数。
- 防开放重定向：登录 `next` 参数仅放行站内相对路径，拦截 `//evil.com` 与反斜杠绕过。
- 防 Host 头注入：新增 `BLOG_CANONICAL_URL` / `BLOG_TRUSTED_HOSTS` 配置，绝对 URL 不再信任请求 Host；nginx 新增 CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy 安全响应头。
- 生产环境未设置 `BLOG_SECRET_KEY` 时直接拒绝启动（避免随机密钥导致登录态与加密字段失效）。
- 评论 / 回复 / 点赞接口按 IP 频率限制（数据库存储，多 worker 共享），超限提示 5 分钟后重试。
- MySQL 恢复加固：恢复前释放连接池（消除元数据锁 MDL 阻塞导致的挂起与库表损坏）、过滤 dump 中的 `LOCK TABLES` 语句、恢复并发锁、恢复后校验 `admin` 表完整性（存在且非空）。

### 变更与修复

- 栏目菜单渲染统一到 `templates/blog/_macros.html`（导航下拉与侧边栏树单一来源，维护只需改一处）。
- 修复文章详情页深色阅读主题下「文章档案」年份文字与背景重合看不清的问题（树形颜色改用 CSS 变量）。
- 「账户邮箱」与「SMTP 邮件设置」合并为后台「账户邮件设置」页，旧地址自动跳转；两表单独立提交互不干扰。
- 后台「站点设置 / 关于我 / 账户邮件设置」宽度统一为与文章页等宽，保存按钮统一右对齐；后台左侧菜单加宽（clamp 自适应）。
- 背景图库改自适应网格（auto-fill），缩略图不再因页面变宽而拉伸失真；风格切换器英文文案简写（BG 1…BG 10、Ink Wash、Lake View）。
- 前台导航移除「退出登录」按钮，退出统一收进后台侧边栏。
- SQLite 备份改用 `VACUUM INTO` 一致性快照；备份文件名精确到毫秒避免重名。
- MySQL 恢复不再卡住页面：子进程 120 秒超时 + stderr 捕获，超时与失败均给出明确报错。
- 数据库备份页风险提示改为可关闭；SQLite 恢复后提示需手动重启服务。
- 表单错误信息国际化（`flash_form_errors` 统一输出多语言错误）。
- 会话加载与错误处理容错：数据库异常时降级为匿名访问、错误页渲染失败退回纯 HTML，避免全站 500。

### 配置与文档

- `.env.example` 补全全部配置项（邮件、反向代理、找回令牌有效期），默认注释由用户按需开启。
- `.env.docker.example` 与 docker-compose 补齐 SMTP 邮件组（`BLOG_MAIL_*`）与 `BLOG_RESET_TOKEN_MAX_AGE`；compose 新增 `backups` 卷，默认不再直接暴露 5000/3306 端口。
- 数据库恢复页新增醒目的风险提示。
- 中英文更新日志同步；i18n 词条重新编译。
